# Product baseline — 2026-09-17 재설계

이 문서는 목표 설계입니다. 구현 완료 여부는 루트 ACTIVE.md를 따릅니다.

## 제품과 첫 사용자

자료를 모으는 데서 끝나지 않고, 읽기 좋은 정리글과 재사용 지식을 쌓아 회사 업무에 사용하는 운영 공간입니다. 첫 사용자는 로컬 PC에서 Obsidian과 웹을 함께 쓰는 단일 운영자입니다. 여러 회사에 제공하는 B2B 제품은 다음 확장 단계입니다.

사용자가 확정한 첫 실사용 목표는 **범용 자료 → 정리글 → 회사 지식**입니다. 기존 저장소와 Vault를 유지하며, 새 제품을 다시 만들거나 개인 Vault를 합치지 않습니다.

## 설계 이력과 확정 기준

아래는 데스크톱에서 진행한 설계 대화와 맥북에서 확인한 구현을 다음 세션에 전달하기 위한 결정 요약입니다. 대화 전문이나 첨부 자료를 대체하는 원본 기록은 아니며, 과거 개인 시스템의 기능을 이 저장소에 구현된 것으로 간주하지 않습니다.

| 변화 | 이유와 현재 적용하는 결정 |
|---|---|
| 개인 KnowledgeOS에서 출발 | Raw 보존, 축적되는 Wiki, 필요한 맥락만 읽는 Context 계층을 채택. 단순한 폴더 생성이나 매번 원문을 다시 읽는 방식에서 벗어나는 것이 목적 |
| Human·Project 계층 추가 | 지식이 사용자의 판단과 실제 산출물에 연결되도록 함. 개인 가치관·목표를 모든 기술 질문에 선로딩하지 않음 |
| Raw → Wiki 사이에 Article 추가 | 짧은 개념 요약만으로 사례·수치·코드와 글의 흐름이 사라졌음. 먼저 원문에 충실하고 독립적으로 읽을 수 있는 정리글을 만듦 |
| 자동 Wiki 생성에서 선택적 반영으로 변경 | Article과 Wiki 중복 및 파일 증식 방지. 기존 지식 보강·출처 간 연결·반복 활용이 있을 때만 Wiki를 제안하며 생성 0개도 정상 |
| 부가 산출물과 문체 정리 | 반복적인 검증 문구·관찰자 문체·요청하지 않은 TXT와 보고서가 읽기를 방해했음. 직접적이고 자연스러운 정리글, 날짜별 통합 로그를 기본으로 함 |
| 개인 지식과 Business OS 분리 | 개인 자료의 소유권을 유지하면서 회사 지식을 실제 업무·승인·측정에 연결. 주제마다 Vault를 늘리기보다 개인/회사 소유 경계를 우선 |
| 범용 Kernel + 업무 Pack 방향 채택 | 주제·업종·도구에 묶이지 않는 공통 계약을 두고, 첫 회사 업무 후보인 GEO/AEO는 후속 Pack으로 연결 |
| 광범위한 운영 플랫폼보다 지식 흐름 우선 | 골격·Demo·가짜 DB 테스트를 제품 완성으로 오인하지 않도록 M2를 재계획. 자료 → Article → 선택적 Wiki → 재사용을 먼저 검증 |
| 맥북에서 M2.1 공통 서비스 구현 | UI별로 생성 로직을 복제하지 않고 CLI로 Raw/Article 경로부터 검증. 실제 API 연결과 합성 자료 생성은 확인했지만 DB 복구·실사용 품질 검토는 남음 |
| 처리 이력을 DB에 연결 | 재실행 비용과 중복을 통제하기 위해 workspace별 작업/시도/호출 사용량을 보존. 명시적 재시도에 상한을 두고 과금 불명·강제 종료는 자동 재실행하지 않음. 파일과 DB의 장애 복구는 다음 단계로 구분 |
| 웹 중심의 설치 후 사용 흐름으로 구체화 | 파일·키·명령을 사용자가 따로 관리하는 부담을 줄임. 웹에서 Vault 연결·설정·자료 가져오기·읽기·검토를 수행하고 Obsidian은 같은 파일을 편집. README는 사용자 안내, 개발 인계는 CONTRIBUTING/ACTIVE에 둠 |

일상 자료 처리의 기본 산출물은 **불변 Raw 1개 + 대표 Article 1개**입니다. 같은 요청은 기존 결과를 재사용합니다. 입력 내용·생성 정책이 바뀐 별도 버전은 계보를 남기며, 사용자 수정본을 자동으로 교체하지 않습니다. 새 콘텐츠 작성은 저장된 Article/Wiki를 재사용하는 별도 작업입니다.

이전 개인 시스템의 QuickAdd/API 연결·Wiki 승인 기능과 개인 프로필은 이 저장소로 자동 이전되지 않았습니다. 당시 Wiki 생성 개수 제한이나 특정 검색 도구 도입 기준도 회사 제품의 구현된 정책이 아닙니다. 여기서는 실제 변경 범위와 재사용 가치를 기준으로 검증합니다.

이전의 작은 합성 검색 평가나 문자 수 예산은 실사용 검색 성능·실제 토큰 수·절감률의 증거가 아닙니다. 모델이 바뀌어도 품질과 비용은 같은 자료로 다시 비교합니다. 기존 결정을 개선할 수 있지만, 해결할 문제와 변경 이유를 이 문서에 남깁니다.

## 첫 릴리스에서 끝까지 되는 일

1. 사용자가 웹에서 파일·본문을 추가하거나 연결한 Vault의 글·메모·코드·자막을 선택해 처리를 요청합니다. Inbox 폴더에 직접 넣는 방식도 유지합니다.
2. 시스템은 원본을 보존하고, 중복 여부와 읽을 수 있는 범위를 확인합니다.
3. 원문 내용·사례·수치·코드를 살린 Article 한 개를 만듭니다. 요약 길이는 목적에 따라 선택합니다.
4. Article만으로 충분하면 종료합니다. 재사용 가치가 있을 때 기존 Wiki 보강 또는 필요한 새 개념을 제안합니다.
5. 사용자는 수정할 문서와 실제 변경 내용을 보고 승인합니다. 승인한 버전만 반영됩니다.
6. 다음 질문·업무에서 저장된 Article/Wiki의 필요한 부분을 찾아 사용합니다.

URL만 있는 자료는 본문 수집이 끝나기 전까지 '본문 필요' 상태입니다. 첫 구현은 붙여넣기·파일·제공된 자막을 우선하며, 웹 수집·YouTube 자막 API는 같은 입력 계약의 후속 Adapter입니다.

## 웹 중심의 첫 사용과 일상 흐름

이 절은 완성할 사용 흐름입니다. 현재 웹은 로컬 Vault 경로·포함 폴더·읽기/원문 저장 권한을 설정하고, 기존 노트 읽기·파일/본문 Raw 저장·수동 새로고침·Obsidian 열기 URI를 제공합니다. 연결과 원문은 재실행 뒤에도 유지됩니다. 별도 테스트 보관함을 한 번의 버튼으로 만들 수 있습니다. 웹 AI 설정/처리·지속 작업·자동 설치는 미구현입니다. 기존 Control Tower를 확장하고 별도 웹 제품이나 두 번째 문서 정본을 만들지 않습니다.

### 처음 한 번 설정

1. **앱 실행:** 로컬 실행기가 필요한 서비스와 DB 준비 상태를 확인하고 브라우저를 엽니다. 개발용 실행 명령은 유지하되 일반 사용자의 일상 작업에는 터미널을 요구하지 않습니다. 설치 패키지·DB 자동 준비는 아직 구현되지 않았습니다.
2. **보관함 연결:** 기존 Vault 연결 또는 새 보관함 만들기를 선택합니다. 경로·소유 영역·포함할 폴더·인식 가능한 파일 수를 미리 보여줍니다. 기존 Vault는 먼저 읽기 전용으로 연결하고, 처리 결과를 쓸 폴더를 확인한 뒤 쓰기를 활성화합니다. 기존 문서를 새 스키마에 맞춰 일괄 변경하지 않습니다.
3. **선택적 AI 설정:** 로컬에 설정된 키는 값을 다시 보여주지 않고 사용 가능 상태를 표시합니다. 새 키는 설정 화면에서 입력하고 로컬 비밀 저장소에 보관하는 경로를 마련합니다. 키 없이도 자료를 읽을 수 있으며, 유료 연결 검사는 별도 명시적 동작입니다. 기본 모델과 호출 상한을 제공하고 고급 설정은 접습니다.
4. **첫 자료 확인:** 샘플 또는 사용자가 고른 자료 한 건으로 읽기·처리 결과 위치·Obsidian에서 열기를 확인합니다. 설정을 다시 열거나 앱을 재시작해도 연결을 기억해야 합니다.

### 매일 사용하는 화면

| 화면 | 사용자 작업 | 보여줄 상태와 복구 경로 |
|---|---|---|
| 홈 | 자료 추가, 최근 글 열기, 확인할 작업으로 이동 | 진행 중·실패·검토 필요. 회사 KPI Demo를 개인의 실적처럼 표시하지 않음 |
| 자료실 | 연결한 Vault 문서와 가져온 자료를 검색·읽기 | 원문/Article/Wiki 관계, 출처, 마지막 파일 변경, 인덱스 갱신 상태, Obsidian에서 열기 |
| 자료 추가 | 파일 드롭, 본문 붙여넣기, URL 입력, Vault 문서 선택 | 처리할 본문·길이·출처·저장 위치·중복·지원 여부를 먼저 확인. 저장만/AI 정리하기를 구분 |
| 문서 상세 | 원문과 정리글을 나란히 읽고 기존 지식 연결 확인 | 원문 보존, 검토 상태, 수동 수정 충돌. 웹의 일반 본문 편집은 후속이며 처음에는 Obsidian에서 편집 |
| 작업·검토 | 대기·진행·실패 확인, 취소/재시도, Wiki 변경 검토 | 실패 이유와 해결 동작, 사용량, 변경 diff. AI 호출 여부가 불명인 작업은 무조건 재호출하지 않음 |
| 설정 | Vault·수집 폴더·AI·사용량·저장 위치·서비스 상태 관리 | 키 미설정/경로 분리/DB 정지 등을 구분하고 재연결·다시 확인·설정 열기 제공 |

Vault에서 문서를 읽는 것은 AI 전송이나 재가공 요청이 아닙니다. 기존 노트에 ID가 없어도 읽을 수 있어야 하며, 사용자가 선택한 자료만 처리 계약으로 가져옵니다. Obsidian이 없어도 웹에서 읽기·처리를 할 수 있고, 미설치 상태의 'Obsidian에서 열기'에는 설치/연결 안내를 제공합니다.

웹 자료 수집은 **URL → 본문 추출 → 미리보기 → Raw 저장 → 필요할 때 Article** 순서입니다. 임의 웹사이트 화면을 그대로 내장하는 브라우저를 만들지 않습니다. 로그인·유료벽·추출 실패·지원하지 않는 자막은 이유를 표시하고 직접 본문/파일을 제공하는 경로를 둡니다. 수집과 AI 처리를 나눠 가져오기만 했는데 과금되는 일을 방지합니다.

설치 편의성의 완료 기준은 새 환경에서 일반 사용자가 설정 파일·SQL·CLI를 직접 수정하지 않고 보관함 연결, 첫 자료 읽기/처리, 재실행을 마치는 것입니다. 설정 화면만 만들고 DB·서비스 실행을 사용자에게 그대로 떠넘긴 상태는 완료가 아닙니다. 구체적인 로컬 패키징 방식은 M2.2에서 검증하며 현재 PostgreSQL 정본 설계를 임의로 바꾸지 않습니다.

## 글쓰기 품질

- Article은 정보 전달용 글입니다. '원문은 설명합니다/경험이 소개됩니다' 같은 관찰자 문체로 바꾸지 않습니다.
- 원문에 있는 세부 정보와 유의점을 보존하되, AI가 내용을 만들어 보충하지 않습니다.
- 매 문단에 검증·불확실성 문구나 출처 ID를 반복하지 않습니다. 출처는 속성과 필요한 연결에 모읍니다.
- 정리 작업과 별도 사실 검증 작업을 구분합니다. 저장된 출처의 주장을 회사의 공식 정책·입증된 사실로 자동 승격하지 않습니다.
- 긴 글은 구간별로 처리하고 전체 내용 대조를 거칩니다. 토큰 한도로 뒷부분이 사라진 글을 완료 처리하지 않습니다.
- Wiki는 Article의 복사본이 아니라 반복 사용하는 개념·구분·관계와 상세 Article 연결입니다.
- 기존 글을 재생성할 때 사용자 수정본을 덮어쓰지 않고 차이를 제시합니다.

## 분류와 화면

source_type(수집 매체), domain(주제), purpose(사용 목적)는 분리합니다. 예를 들어 YouTube는 source_type이고 marketing은 domain입니다. 기본 domain은 general이며 필요한 주제를 설정으로 추가합니다. 건강·코딩 폴더를 모든 회사에 강제하지 않습니다.

첫 웹 화면은 자료 대기열, 처리 결과, 실패/본문 필요, Wiki 변경 검토, 최근 지식을 보여줍니다. 지표는 실제 처리 건수·실패/대기·처리 시간에서 시작하며 모델 사용량을 덧붙입니다. 관측되지 않은 값은 0이 아니라 미측정입니다. 회사 성과 KPI와 추천은 실제 입력이 연결된 뒤 추가합니다.

## 범위와 단계

| 계층 | 지금 만드는 범위 | 이후 필요할 때 |
|---|---|---|
| 공통 기반 | 작업공간, 문서 참조, 처리 작업, 승인, 이벤트 | 팀 권한, 다중 회사 운영 |
| 지식 기능 | Raw/Article/Wiki, 부분 검색, 원문 추적 | 수집 Adapter, 고급 검색 |
| 업무 Pack | 연결 가능한 경계만 유지 | 첫 GEO/AEO 콘텐츠 개선 루프 |
| Industry Pack | 구현하지 않음 | 실제 회사 간 공통 패턴을 확인한 뒤 |

복잡한 Multi-Agent, Vector DB, 의미 캐시, CRM 전체, 광고 자동 집행, 플러그인 시장, 자율 규칙 변경은 첫 릴리스에서 제외합니다. n8n은 검증된 업무를 연결할 때 사용하는 실행 Adapter이지 필수 기반이 아닙니다.

## 준비 정보와 완료의 의미

- 기본 자료 처리: 작업공간 이름·Vault 위치만 있으면 시작합니다. 회사 목표는 만들거나 추측하지 않습니다.
- 회사별 전략·성과 평가: Company Profile, 대상 고객, 제공 가치, 핵심 목표·측정 방법이 필요합니다.
