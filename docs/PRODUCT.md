# Product baseline — 2026-09-17 재설계

이 문서는 목표 설계입니다. 구현 완료 여부는 루트 ACTIVE.md를 따릅니다.

## 제품과 첫 사용자

자료를 모으는 데서 끝나지 않고, 읽기 좋은 정리글과 재사용 지식을 쌓아 회사 업무에 사용하는 운영 공간입니다. 첫 사용자는 로컬 PC에서 Obsidian과 웹을 함께 쓰는 단일 운영자입니다. 여러 회사에 제공하는 B2B 제품은 다음 확장 단계입니다.

사용자가 확정한 첫 실사용 목표는 **범용 자료 → 정리글 → 회사 지식**입니다. 기존 저장소와 Vault를 유지하며, 새 제품을 다시 만들거나 개인 Vault를 합치지 않습니다.

## 첫 릴리스에서 끝까지 되는 일

1. 사용자가 글·문서·메모·코드·자막 본문을 Inbox에 넣고 처리를 요청합니다.
2. 시스템은 원본을 보존하고, 중복 여부와 읽을 수 있는 범위를 확인합니다.
3. 원문 내용·사례·수치·코드를 살린 Article 한 개를 만듭니다. 요약 길이는 목적에 따라 선택합니다.
4. Article만으로 충분하면 종료합니다. 재사용 가치가 있을 때 기존 Wiki 보강 또는 필요한 새 개념을 제안합니다.
5. 사용자는 수정할 문서와 실제 변경 내용을 보고 승인합니다. 승인한 버전만 반영됩니다.
6. 다음 질문·업무에서 저장된 Article/Wiki의 필요한 부분을 찾아 사용합니다.

URL만 있는 자료는 본문 수집이 끝나기 전까지 '본문 필요' 상태입니다. 첫 구현은 붙여넣기·파일·제공된 자막을 우선하며, 웹 수집·YouTube 자막 API는 같은 입력 계약의 후속 Adapter입니다.

## 글쓰기 품질

- Article은 정보 전달용 글입니다. '원문은 설명합니다/경험이 소개됩니다' 같은 관찰자 문체로 바꾸지 않습니다.
- 원문에 있는 세부 정보와 유의점을 보존하되, AI가 내용을 만들어 보충하지 않습니다.
- 매 문단에 검증·불확실성 문구나 출처 ID를 반복하지 않습니다. 출처는 속성과 필요한 연결에 모읍니다.
- 정리 작업과 별도 사실 검증 작업을 구분합니다. 저장된 출처의 주장을 회사의 공식 정책·입증된 사실로 자동 승격하지 않습니다.
- 긴 글은 구간별로 처리하고 전체 내용 대조를 거칩니다. 토큰 한도로 뒷부분이 사라진 글을 완료 처리하지 않습니다.
- Wiki는 Article의 복사본이 아니라 반복 사용하는 개념·구분·관계와 상세 Article 연결입니다.
- 기존 글을 재생성할 때 사용자 수정본을 덮어쓰지 않고 차이를 제시합니다.

## 분류와 화면

source_type(수집 매체), domain(주제), purpose(사용 목적)는 분리합니다. 예를 들어 YouTube는 source_type이고 marketing은 domain입니다. 기본 domain은 general이며 필요한 주제를 설정으로 추가합니다. 건강·코딩 폴더를 모든 회사에 강제하지 않습니다.

첫 웹 화면은 자료 대기열, 처리 결과, 실패/본문 필요, Wiki 변경 검토, 최근 지식을 보여줍니다. 지표는 실제 처리 건수·실패/대기·처리 시간에서 시작하며 모델 사용량을 덧붙입니다. 관측되지 않은 값은 0이 아니라 미측정입니다. 회사 성과 KPI와 추천은 실제 입력이 연결된 뒤 추가합니다.

## 범위와 단계

| 계층 | 지금 만드는 범위 | 이후 필요할 때 |
|---|---|---|
| 공통 기반 | 작업공간, 문서 참조, 처리 작업, 승인, 이벤트 | 팀 권한, 다중 회사 운영 |
| 지식 기능 | Raw/Article/Wiki, 부분 검색, 원문 추적 | 수집 Adapter, 고급 검색 |
| 업무 Pack | 연결 가능한 경계만 유지 | 첫 GEO/AEO 콘텐츠 개선 루프 |
| Industry Pack | 구현하지 않음 | 실제 회사 간 공통 패턴을 확인한 뒤 |

복잡한 Multi-Agent, Vector DB, 의미 캐시, CRM 전체, 광고 자동 집행, 플러그인 시장, 자율 규칙 변경은 첫 릴리스에서 제외합니다. n8n은 검증된 업무를 연결할 때 사용하는 실행 Adapter이지 필수 기반이 아닙니다.

## 준비 정보와 완료의 의미

- 기본 자료 처리: 작업공간 이름·Vault 위치만 있으면 시작합니다. 회사 목표는 만들거나 추측하지 않습니다.
- 회사별 전략·성과 평가: Company Profile, 대상 고객, 제공 가치, 핵심 목표·측정 방법이 필요합니다.
- 개인→회사 자료: 사용자가 선택한 범위와 사용 목적을 확인합니다. 개인 전체 저장소를 스캔하지 않습니다.
- '지식 v1 사용 가능': 자료 입력에서 글·선택적 Wiki·다음 작업 재사용까지 실제로 검증됨.
- '회사 운영 v1': 선택한 실제 업무 한 종류가 실행·측정·개선까지 돌아감.
- 'B2B 제공 가능': 인증·회사 격리·백업 복구·배포·운영 지원까지 별도 검증됨.

첫 번째가 완료됐다고 세 번째까지 완성됐다고 표현하지 않습니다. 진행률 대신 통과한 사용 시나리오와 남은 조건을 보고합니다.
