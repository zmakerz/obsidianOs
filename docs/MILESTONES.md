## M2.0 — 기준선과 Obsidian 사용성 복구

완료 (2026-09-17): 코드 구현·자동 검증과 수동 Obsidian 문서 열기 확인을 마쳤습니다. M2.0의 명시된 범위만 완료이며, 실제 AI 처리·운영 DB·전체 제품의 완성을 의미하지 않습니다. 다음 개발 단계는 M2.1입니다.

구현됨: portable CLI 입력/경로 처리, YAML parser와 kind별 속성·중복 ID 검사, 실제 경로 기반 Wikilink/헤딩/블록/첨부 검사, HOME 도달성, 원문 무변경·실패 fixture. 파일 경로는 인덱스로 조회하며 별칭을 존재하는 파일로 오인하지 않습니다.

수동 확인 완료: 회사 프로필·운영 모델·승격 SOP의 기존 본문이 열리는 것을 확인했습니다. 회사 프로필의 공란은 입력 전 템플릿 상태입니다. 자동 UI end-to-end 검증은 아니며, 일반 Markdown 링크·외부 URL·플러그인 전반의 검증을 완료했다고 주장하지 않습니다.

- 승격 CLI의 standalone --, 누락 값, 알 수 없는 인자, 잘못된 입력 처리와 회귀 테스트.
- bare alias 목적지를 실제 파일 경로|표시명으로 정리. 실제 YAML parser로 kind별 메타데이터와 duplicate ID 검사.
- 링크 검사는 경로·헤딩·첨부·표시명을 구분하고, HOME에서 주요 문서로의 도달성을 확인. 별칭을 파일 존재 증거로 인정하지 않음.
- 깨진 링크/빈 필수 값/중복 ID/자기 링크만 있는 고립 문서 같은 실패 fixture가 실제 실패하도록 테스트.
- 문서의 '실행기/완료/검증' 표현을 실제 동작 범위와 맞추고 기존 파일은 보존.

완료 기준: 문서에 적힌 명령을 임시 Vault에서 실제 실행, HOME 주요 링크 직접 열기 확인, 잘못된 사례에 lint가 실패, 정상 템플릿은 통과. 원본과 실제 회사 문서가 테스트 때문에 변경되지 않음.

## M2.1 — 지속 가능한 자료 → Article 경로

진행 중 (2026-09-17): 첫 로컬 CLI/서비스를 구현했습니다. immutable Raw·문서 ID·중복 반환·수동 수정 충돌·제공 초안/AI Article·날짜별 결과 로그를 연결했습니다. API 연결과 짧은 합성 자료의 실제 Article 생성도 확인했습니다. PostgreSQL 작업 저장과 명시적 로컬 중단 복구는 연결됐으며 긴 자료의 의미적 누락 평가, 실사용 글의 사용자 검토는 남아 있어 M2.1 전체 완료는 아닙니다.

UI보다 공통 서비스와 CLI를 먼저 연결합니다.

- Markdown Adapter, stable 문서 ID, 범용 입력 계약과 파일명, Raw 보존·중복 감지.
- 실제 PostgreSQL 개발/테스트 환경, 버전 migration, 처리 작업/시도/이벤트 repository.
- 원문 충실 Article 생성과 긴 입력 처리. AI 호출은 중앙 Adapter 한 곳; 테스트는 deterministic fixture로 실행.
- 사용자 제공 초안으로도 저장 경로를 검증할 수 있으나, 이를 AI 처리 완료로 표시하지 않음.
- 실제 AI 연동 검증은 비밀키를 안전하게 설정하고 비용/입력 범위를 확인한 뒤 별도 실시.
- 중단 복구, 재시도, 사용자 편집 충돌, 일일 로그 append, 본문 없는 URL의 needs-input 처리.
- DB pool/범위 제약/transaction 테스트를 운영 경로에 적용.

완료 기준: 마케팅 글·기술 코드 포함 글·긴 일반 문서로 Raw와 Article 생성, 동일 요청 반복 시 중복 없음, 중단 후 복구, 원문 hash 유지, 수동 수정 보호. 실제 DB rollback과 재시작 테스트 통과. 실사용 AI 글 최소 한 건을 사용자가 문체·내용 보존 기준으로 검토.

### M2.1의 남은 실행 순서

1번 DB 기반과 2번 지속 작업 상태는 2026-09-17 맥북 PostgreSQL 18.6에서 완료했습니다. 3번 로컬 명시적 복구는 2026-09-22에 검증했습니다. 다음 개발은 4번부터 시작하며 기존 Raw/Article 서비스와 테스트를 보존합니다. M2.1 전체는 미완료입니다.

1. **실제 DB 검증 기반 — 완료:** 격리 PostgreSQL 18.6에서 버전·checksum·동시 migration, 프로세스별 재사용 pool, workspace source FK와 Control Tower 서버 Adapter를 검증했습니다. 빈 DB 설치, 재실행, 설치/업그레이드 rollback, 동시 승인·감사 실패 rollback·workspace 분리 자동 테스트 통과. 별도 DB 서버 재시작 후 데이터 보존·풀 재연결도 확인했습니다. 운영 DB는 사용하지 않았습니다. 이력 없는 기존 DB baseline과 일반 사용자 DB 설치 패키지는 아직 없습니다.
2. **지속 작업 상태 — 완료:** 공통 `processSourceJob`와 CLI `--track-job`에 workspace별 요청·job·attempt·event·호출별 사용량을 연결했습니다. 동일 요청/동시 claim, 제한된 명시적 재시도, 협력적 취소, 실패 이유, 새 CLI 프로세스 조회와 workspace 제약을 실제 DB에서 검증했습니다. 부분 성공 사용량과 불명 호출을 구분하며 모델은 모의 응답으로 테스트했습니다. 실행 중 강제 종료의 자동 회수·파일 반영 복구는 3번 범위입니다.
3. **중단 후 복구 — 로컬 명시적 재개 범위 완료:** lease/heartbeat·실행 소유권 검사, 구간/완성 초안 재사용, 게시 hash intent와 부분 로그 재개를 연결했습니다. 실제 자식 프로세스 SIGKILL로 Raw/API/Article/로그 경계의 중단, 동시 복구와 사용자 편집 보존을 검증했습니다. --resume은 같은 기기의 확인된 종료 소유자만 회수하고, 응답/결과 불명은 재호출하지 않고 검토 대상으로 둡니다. 백그라운드 자동 재개, 다른 기기/구형 잠금, 전원 손실 보장은 포함하지 않습니다.
4. **입력 계약과 품질 검증:** Capture 메타데이터와 실제 본문을 분리하는 Adapter를 연결합니다. 마케팅/코드/긴 일반 자료의 앞·중간·끝, 사례·수치·조건·코드 보존을 평가하고 합본의 중복·문체도 검토합니다. 구조 검사 통과를 의미적 누락 없음으로 해석하지 않습니다. 사용자가 선택한 실사용 자료 최소 한 건의 검토를 받습니다.
5. **완료 판정:** 위 실제 DB·장애 복구·자료별 품질 증거를 ACTIVE에 기록한 뒤 M2.1 완료 여부를 판단합니다. M2.2의 웹 쓰기·처리 기능은 이 서비스에 연결합니다. 별도의 Vault 연결/읽기 전용 화면은 먼저 구현할 수 있지만 지속 처리나 전체 단계의 완료로 표시하지 않습니다.

회사 프로필 입력이나 웹 화면 확장을 이 순서의 선행 조건으로 추가하지 않습니다. API 키 설정과 짧은 합성 자료의 실제 호출은 이미 확인했으므로 같은 환경에서 이유 없이 유료 연결 검사를 반복하지 않습니다.

## M2.2 — 웹 설정·자료실 + Obsidian 연결 + 선택적 Wiki

사용자 진입점은 웹입니다. 현재 Vault 경로/폴더/권한 설정·기존 노트 목록/본문 읽기·파일/본문 Raw 저장·설정 복원·수동 갱신·Obsidian URI가 구현됐습니다. 합성 테스트 보관함으로 키/DB 없이 시험할 수 있으며 README에 실제 화면과 절차가 있습니다. 이것은 동기 원문 저장 단계이며 웹 AI/지속 작업이나 M2.2 전체 완료가 아닙니다. macOS Safari → Obsidian 1.13.7 문서 열기/편집 → 웹 새로고침 왕복과 서비스 재시작 뒤 설정·문서 복원을 확인했습니다. 내부 브라우저의 외부 앱 열기는 동작하지 않아 일반 브라우저 사용을 안내합니다. 기존 운영 Demo는 /operations에 보존합니다. 다음 순서로 연결합니다.

1. **설정·읽기:** Vault 경로/범위 등록, 읽기 전용 기존 Markdown 목록·본문·검색, 연결 상태, Obsidian에서 열기. ID 없는 노트를 변경하지 않고도 읽을 수 있어야 합니다. 새 Vault 생성과 기존 Vault 연결을 구분합니다.
2. **첫 자료 처리:** 키 사용 상태/입력과 기본 예산, 파일·본문·Vault 문서 선택, 입력 미리보기, 저장만/AI 정리, 작업 상태, 원문/Article 비교를 M2.1에 연결합니다. 앱 재시작 뒤 설정과 작업을 유지해야 합니다.
3. **웹 자료 수집:** 우선 공개 웹 문서의 URL → 본문 미리보기 → 저장을 연결합니다. 수집 실패 시 붙여넣기 경로를 제공하고, YouTube 자막·PDF 등은 지원 상태를 명시한 개별 Adapter로 확장합니다. 무단 전체 크롤링이나 외부 화면 iframe을 기본으로 하지 않습니다.
4. **재사용·검토:** 부분 검색과 실제 diff/revision에 연결된 선택적 Wiki 승인을 구현합니다. 아래 승인/충돌 조건을 통과해야 합니다.
5. **설치·일상 사용 검증:** 로컬 실행기의 서비스/DB 준비와 재시작, 웹 설정 유지·복구를 확인합니다. 패키지/OS별 DB 준비 방식을 정하고 깨끗한 환경에서 검증합니다. Ctrl+P는 동일 작업을 호출하는 추가 편의 기능으로 연결하며 웹 사용의 필수 플러그인으로 만들지 않습니다.

- Ctrl+P '현재 자료 처리'가 M2.1 서비스를 호출하고 처리 상태/결과 파일을 표시.
- 웹은 동일 작업의 대기·실패·결과·실제 사용량을 조회. Demo와 실제 데이터 구분; 미측정 값은 null/미측정.
- Wiki 변경 필요성 판단, 기존 문서 검색, 실제 diff preview, 범위·revision 결합 승인.
- 승인 전 변경 없음, 반려/만료/수동 수정 뒤 stale approval 반영 차단. 제안 생성과 반영 실행을 명확히 구분.
- Raw/Article 어느 화면에서 요청해도 동일 출처 계보로 작업을 찾음.
- metadata/capsule/section 검색과 후속 질문의 출처 연결. Raw 전체 선로딩 금지.
- 로컬 웹 쓰기 경로의 origin/세션·Vault 경로 제한과 예산 표시.

완료 기준: 새 환경에서 설정 파일·SQL·CLI 직접 편집 없이 Vault 연결 → 기존 노트 읽기 → 웹에서 자료 추가 → Article 확인 → Obsidian에서 열기/수정 → 웹에서 변경 확인이 이어짐. Obsidian에서 넣은 자료도 같은 처리 경로로 연결됨. 서비스 재시작·Vault 경로 분리·수집 실패에 해결 동작이 표시됨. Article로 충분하면 Wiki 0개, 지식 확장에는 승인한 변경만 반영하고 다음 실제 질문에 재사용. 설치/DB 준비가 수동으로 남으면 웹 화면이 있어도 이 사용성 기준은 미완료로 표시.

**지식 v1 사용 가능 판정:** 사용자가 선택한 5~10건을 시작 표본으로 검토하되 건수 자체를 합격 근거로 삼지 않음. 원문 손실·잘못된 파일 변경·중복 생성 0, 미처리/실패 가시성, 문체 수용, 재사용 확인. 사용자의 내용 수정 부담과 시간·토큰 비용을 기록.

## M3 — 첫 회사 운영 Loop

실제 사업이 정해지면 첫 후보는 GEO/AEO 콘텐츠 개선입니다. CRM 전체를 한꺼번에 추가하지 않습니다.

- Company Profile에 실제 제공 가치·고객·목표·담당자 입력.
- 한 바퀴를 '핵심 질문/콘텐츠 자산 하나 개선'으로 정의.
- 자료/회사 지식 → 초안 → 사람 검토 → 승인된 발행 → 결과 기록 → 다음 개선 제안.
- 첫 측정은 수동 입력/CSV도 허용. AI 인용, 유입, 문의 등 사용할 지표의 정의·출처·시점을 정함.
- 관측 기록이 없으면 추천을 꾸미지 않음. 새 규칙/SOP는 변경 제안으로 남기고 승인 후 채택.
- 외부 API 발행 자동화는 수동 흐름과 실패 복구를 검증한 뒤 하나씩 연결.

완료 기준: 실제 콘텐츠/업무 한 종류에서 결과를 기록하고 그 결과가 다음 실행의 판단에 반영됨. 발행을 수동으로 했는지 Adapter로 했는지 구분. 이것이 내부 회사 운영 v1의 조건이며 B2B 출시 조건은 아님.

## M4 — B2B 제공 준비와 필요한 확장

- 인증·조직/작업공간 멤버십·역할, 교차 회사 접근 차단, 데이터/키 격리.
- 실제 고객 문서를 코드 배포와 분리, 설정 기반 Vault 연결, migration/백업 복원 훈련.
- 승인·실행 연결의 만료/취소/재실행 보호, 운영 관측과 비용 제한, 첫 외부 연동의 복구.
- 설치·업데이트·지원 절차와 고객별 설정. 반복 확인된 업무만 Pack으로 묶음.

완료 기준: 다른 회사의 데이터가 보이지 않음, 백업에서 복원, 업그레이드 후 기존 자료/작업 유지, 승인하지 않은 외부 효과 없음. Industry Pack, 다중 Agent, 고급 RAG는 실사용 문제가 확인될 때만 추가.

## 다음 개발 요청의 실행 범위

'다음으로 진행' 요청이면 ACTIVE에서 미완료 단계와 다음 행동을 확인합니다. 특정 단계가 지정되면 그 범위의 구현·검증을 우선합니다. 필요한 설정 선택은 진행 가능한 부분을 먼저 완료한 뒤 묻습니다. Company Profile 공란을 범용 기반 개발의 차단 사유로 삼지 않습니다.

이후 단계는 앞 단계의 실제 실패 사례를 반영해 조정합니다. 모든 기능을 먼저 명세하거나 패키지를 미리 생성하지 않습니다.
